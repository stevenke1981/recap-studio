# 發布包模板

本檔供 `recap-render-publish` 製作 `08_publish/` 內容。`【推論】`者為設計值，依頻道數據調整；`【查核】`者上傳前須重讀 YouTube 官方頁或 Studio 畫面。

---

## 1. 標題

### 1.1 三種公式

**A. 古典短篇式（夜燈模式一）**
`篇名｜結果／懸念（問句或對比）｜系列名`
- 例（研究 01 實例，事實）：`狐嫁女｜荒宅婚宴，一只金爵牽出十年舊事｜聊齋志異・夜燈說書`
- 適用：單一故事、篇幅 10–25 分鐘之短中篇。

**B. 歷史人物式（夜燈模式二）**
`人物／事件：反差問句｜頻道名`
- 例（研究 01 實例，事實）：`于謙：守住北京，為何仍被處死？｜夜燈說書`
- 適用：人物傳記、史事，懸念來自「結果與預期相反」。

**C. 長片「一口氣看完」式**
`一口氣看完《作品名》：一句核心懸念｜完整長篇解說`
- 例：`一口氣看完《某作品》：他一步步走上權力頂端，代價是什麼？｜完整長篇解說`
- 適用：30–180 分鐘長片。
- 依據：研究 01 §7 觀察之搜尋慣例（「一口氣看完」＋作品名），流量效果【推論】，未驗證。
- 注意：標題用作品名僅作指稱，不得暗示官方、授權或原作者背書。

### 1.2 規則
- 長度：YouTube 標題上限約 100 字元【查核】。
- 懸念與縮圖互補、不重複：標題給問題，縮圖給反差或畫面。
- 不得誤導：標題與內容不符之誤導性中繼資料，平台可能限制【查核】。
- 每片至少列 3 個候選，選定者置於 `description.md` 首節，並標註理由。

## 2. 縮圖

### 2.1 規格
- 尺寸：1280×720，16:9；PNG 或 JPG。
- 檔案：`08_publish/thumbnail.png`；大小上限 2 MB【查核】。

### 2.2 版面（研究 01 §1 觀察之夜燈縮圖模式，事實）
- 主體：寫實 AI 人物或場景，整體加暗，突出主角。
- 篇名：大字、粗體、高對比（金色或白字），佔畫面寬度約 60–80%。
- 副文：1–2 行反差問句，白字，關鍵詞金色。
- 角落：頻道名或小徽章，字小但可辨識。
- 避免：與標題逐字重複；小於 40 px 之字；原作角色、商標或電影海報為主視覺；冒充真人。

### 2.3 產製路徑
- **路徑 A（推薦）**：`chatgpt-image-gen` 生成無字底圖，預留左側或中央文字區；再以 Pillow 疊字。
- **路徑 B（離線）**：直接使用既有 `04_assets/images/` 之一張圖，以 Pillow 疊字。

Pillow 疊字參考（字型路徑為 Windows 預設，使用前確認存在）：

```python
from PIL import Image, ImageDraw, ImageFont
from pathlib import Path

FONT = Path(r"C:\Windows\Fonts\msjhbd.ttc")      # 微軟正黑體 Bold；不存在則改 msjh.ttc
W, H = 1280, 720
bg = Image.open(r"D:\...\base.png").convert("RGB").resize((W, H))
shade = Image.new("RGB", (W, H), (0, 0, 0))
bg = Image.blend(bg, shade, 0.35)                 # 加暗
draw = ImageDraw.Draw(bg)
title_font = ImageFont.truetype(str(FONT), 110)
sub_font = ImageFont.truetype(str(FONT), 52)
draw.text((70, 200), "篇名大字", font=title_font, fill=(230, 180, 90),
          stroke_width=6, stroke_fill=(0, 0, 0))
draw.text((70, 380), "反差問句一行", font=sub_font, fill=(245, 245, 245),
          stroke_width=3, stroke_fill=(0, 0, 0))
bg.save(r"<repo>\projects\<slug>\08_publish\thumbnail.png")
```

### 2.4 自查
- [ ] 1280×720，檔案 ≤ 2 MB。
- [ ] 手機縮小至 160 px 寬仍可讀篇名。
- [ ] 逼真 AI 人物或真實事件 → 同 CP-4，說明欄與 Studio 皆揭露。
- [ ] 不含原作畫面、原作標誌或他人商標。

## 3. 說明欄（`08_publish/description.md`）

檔案結構如下，依序填寫。

```markdown
# 發布包：{片名}

## 標題候選
1. （公式 A/B/C）……
2. ……
3. ……
選定：#{n}（理由：……）

---
## 說明欄（貼至 YouTube）

{簡介：2–3 句，點出懸念，不劇透結局。}

{本片性質：以白話改編之原創評論，或原創解說；角色對白與銜接含戲劇化增寫，並非原文逐字朗讀。}

章節
{貼入 08_publish/chapters.txt 全文，第一行必為 0:00}

來源與史料
- {書名・卷・篇}（{版本或出版者}）：{用於本片之哪一段}
- {若為公版原作：寫「本片依公版原作改編」並註明版本}
- {若查無史料：寫「本片未引用外部史料」}

圖像與音樂
- 圖像：{例：本片圖像為 AI 生成之示意插畫，非原作截圖。}
- 公版圖像：{作者}，{年代}，公版；來源：{URL}
- 音樂：{曲名}，{來源}，{授權條款}（{自製者寫「本片配樂為自製」}）

AI 揭露
本片旁白為 AI 合成語音，圖像由 AI 生成。
{若含逼真 AI 人物或場景，加：本片含 AI 生成之寫實影像，描繪之人物與事件為虛構或示意。}

改編說明
{哪裡改編、哪裡增寫、史料有歧見處如何處理，例：「材料有歧見處，本集不將其定為史實。」}

留言問題
{一個開放式問題，與本集評論主軸直接相關，例：「你覺得他當年為何不離開？」}

{訂閱呼籲：一句。}

{#標籤：3–5 個}
```

### 3.1 欄位要點
- **章節**：格式與規則見 SKILL.md 之 make_chapters 說明；貼上後以 YouTube 預覽確認可點擊。
- **來源與史料**：每一則須能回查（書名、卷、篇、版本）。查不到即明寫，不杜撰頁碼或版本。
- **圖像署名與授權**：AI 生成圖通常不需署名，但須寫明為 AI 生成；公版或授權圖須寫作者、年代、來源與授權。
- **AI 揭露**：說明欄文字揭露為平台 Studio 勾選之外的補充，兩者皆須做。
- **改編說明**：白話改編、戲劇化增寫、史料分歧，皆須誠實揭露。此段兼具合規與信任功能。
- **留言問題**：每片一個，須能引發觀點而非二選一；與結尾意象相扣為佳【推論】。
- **標籤**：3–5 個；YouTube 會顯示前幾個於標題上方【查核】。

### 3.2 完整性檢查
- [ ] 第一章節行為 `0:00`，章節數 ≥ 3。
- [ ] 來源、圖像、音樂、AI 揭露、改編說明五段皆存在。
- [ ] 留言問題為開放式，且僅一個。
- [ ] 無引文超過 2–3 句之逐字引用；引文皆註明出處。
