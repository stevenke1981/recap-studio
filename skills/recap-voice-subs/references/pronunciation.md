# 發音詞典與多音字／古文人名地名參考

本檔配合 `recap-voice-subs` 使用。機制重點（已讀 `scripts/tts_batch.py` 確認）：

- `project.json` 之 `pronunciations` 為 `{原字詞: 替換寫法}`。替換**只作用於送往 edge-tts 的文字**；`05_audio/manifest.json` 之 `subs` 與 `06_subs/full.srt` 仍顯示原文。
- 替換為**子字串全域取代**，長詞優先（最長匹配）。鍵不可為單一常用字（如 `"行"`），否則所有「行」皆被改。
- `text_hash = sha1(voice + tts_rate + 替換後文字)`；改詞典只會讓受影響句段重生，其餘句段走快取。
- edge-tts 無音素標註（無 SSML `phoneme`），**無法直接指定拼音**，只能以「字」替換。

## 1. 替換寫法原則

| 順位 | 方法 | 例 | 注意 |
|---|---|---|---|
| 1 | 同義詞（語意不變） | `"重新": "再度"` | 最穩；語意須經主人確認 |
| 2 | 同音異字（讀音確定、字形不易誤會） | `"尉遲": "玉遲"` | 替換字本身須是無歧義讀音 |
| 3 | 以完整專名作鍵 | `"沈括": "審括"` | 避免單字鍵誤傷其他詞 |
| 4 | 不替換，改寫稿件 | 將括號註解改寫入句中 | 若上述皆不可行 |

- 替換後的字可能在語意上「不通」，無妨，因字幕不顯示；但**不得改變劇情語意**。
- 每次新增替換，須在 `project.json` 同步記錄，並以 `tts_batch --only <章>` 重生受影響句段。

## 2. 常見易錯範例（候選清單）

> 以下為依一般漢語拼音知識整理之**候選**，不是本機實測結論。每條須以試聽或聽寫抽查確認（見第 4 節）。替換寫法亦為「候選」，確認無誤方可入 `project.json`。

### 2.1 多音字（現代語境）

| 字 | 讀音 | 易錯情境示例 | 建議處理 |
|---|---|---|---|
| 行 | xíng／háng | 行長（háng zhǎng）、銀行（háng） | 以詞為鍵：`"行長": "航長"`（僅 TTS） |
| 重 | zhòng／chóng | 重新（chóng xīn）、重複（chóng fù） | 同義改寫：`"重新": "再度"` |
| 長 | cháng／zhǎng | 長安（cháng ān）、長大（zhǎng dà） | 專名鍵：`"長安": "常安"` |
| 了 | le／liǎo | 了結（liǎo jié）、了解（liǎo jiě） | 多數上下文可判；聽寫抽查再定 |
| 得 | de／dé／děi | 得到（dé dào）、要得（děi） | 一般不替換；列入聽寫抽查 |
| 著 | zhe／zhuó／zháo | 著名（zhù míng）、著急（zháo jí） | 專名或成語整詞鍵 |
| 數 | shù／shǔ／shuò | 數學（shù xué）、數數（shǔ shu） | 整詞鍵；「數數」可改寫為「點數」並確認語意 |
| 樂 | lè／yuè | 音樂（yuè）、快樂（lè） | 通常可判；專名鍵 `"樂毅"` 見 2.2 |
| 傳 | chuán／zhuàn | 傳記（zhuàn）、傳說（chuán shuō） | 整詞鍵抽查；替換字須同讀（如 zhuàn 之字），無合適同讀字時改寫稿件 |
| 降 | jiàng／xiáng | 投降（xiáng）、降低（jiàng dī） | 整詞鍵 `"投降"` 通常可判，抽查即可 |
| 還 | hái／huán | 還是（hái shì）、歸還（guī huán） | 通常可判；抽查 |
| 藏 | cáng／zàng | 西藏（xī zàng）、收藏（shōu cáng） | 專名鍵 `"西藏"` 不必替換，抽查即可 |
| 薄 | báo／bó | 薄弱（bó ruò）、薄紙（báo zhǐ） | 整詞鍵抽查 |
| 角 | jué／jiǎo | 角色（jué sè）、牛角（niú jiǎo） | 整詞鍵抽查 |
| 曝 | bào／pù | 曝光（bào guāng）、一曝十寒（pù） | 成語整詞鍵 |
| 盛 | shèng／chéng | 盛大（shèng dà）、盛飯（chéng fàn） | 抽查 |
| 曾 | zēng／céng | 曾國藩（zēng guó fān）、曾經（céng jīng） | 姓氏鍵：`"曾國藩": "增國藩"` |
| 沈 | shěn／chén | 沈括（shěn kuò）、沉沒（chén mò，不同字） | 專名鍵：`"沈括": "審括"` |
| 差 | chà／chā／chāi／cī | 差距（chā jù）、出差（chāi） | 整詞鍵抽查 |

### 2.2 古文人名、地名（易被以現代讀音誤讀）

| 原字詞 | 正讀 | 易錯讀 | 候選替換（僅 TTS） | 備註 |
|---|---|---|---|---|
| 尉遲恭 | yù chí gōng | wèi chí | `"尉遲": "玉遲"` | 「尉」為姓時讀 yù |
| 呂布 | lǚ bù | 依 TTS 實際讀法而定（未實測） | `"呂布": "旅布"` | 僅在聽寫確認誤讀時才加入 |
| 樂毅 | yuè yì | lè yì | `"樂毅": "月義"` | 戰國人名 |
| 解縉 | xiè jìn | jiě jìn | `"解縉": "謝縉"` | 「解」為姓讀 xiè |
| 宓妃 | fú fēi | mì fēi | `"宓妃": "伏妃"` | 神話人物 |
| 亳州 | bó zhōu | háo zhōu | `"亳州": "薄州"` | 地名，安徽 |
| 單于 | chán yú | dān yú | `"單于": "蟬于"` | 匈奴君主稱號；替換字形怪異，須試聽 |
| 朴（姓） | piáo | pǔ | `"朴常達": "瓢常達"`（以完整人名為鍵） | 替換為子字串取代，單字鍵「朴」會誤傷「樸」以外之詞與其他專名，故須整名為鍵 |
| 重慶 | chóng qìng | zhòng qìng | `"重慶": "崇慶"` | `project.json` 既有範例 |
| 長安 | cháng ān | zhǎng ān | `"長安": "常安"` | 古都名 |

> 「朴」「樸」為不同字，鍵須精確到字形，避免替換錯字。

## 3. 寫法範例（可直接複製進 `project.json`，皆為候選）

```json
"pronunciations": {
  "重慶": "崇慶",
  "重新": "再度",
  "行長": "航長",
  "尉遲": "玉遲",
  "沈括": "審括",
  "亳州": "薄州"
}
```

- 鍵一律採「完整詞」，不用單字（除非該字在全稿皆同讀）。
- 同一字多種讀音時，不以單字鍵處理；改用詞鍵或改寫稿件。
- 替換寫法不含標點，不改變句數與長度判斷（字幕仍以原文切）。

## 4. 偵測流程

### 4.1 掃描（寫稿後、合成前）

1. 找出高風險字（第 2.1 表之字）在稿件中的上下文：

   ```
   rg -n -o ".{0,3}[行重長了得著數樂傳降還藏薄角曝盛曾沈尉解宓亳].{0,3}" <repo>\projects\<slug>\03_storyboard\shots.json
   ```

   （實際字集依稿件調整；若 Windows 主控台顯示亂碼，以 `PYTHONIOENCODING=utf-8` 執行或改輸出至檔案再讀。）

2. 每筆判讀讀音；能判定者不處理，無法判定者列入「待聽」清單。
3. 專名（人名、地名）一次列出，逐一對第 2.2 表。

### 4.2 合成後聽寫抽查

1. 以 `tts_batch` 生成（至少目標章）。
2. 對 `05_audio/<segment_id>.mp3` 做語音辨識，得到轉寫文字，與 `shots.json` 之 `text` 比對（字級差異、同音錯字）。
   - 首選 `faster-whisper`，**但依研究報告 03，本機目前匯入失敗（缺 `huggingface_hub`），未修前不可用**。
   - 替代：`qwen3-asr`（本機；ForcedAligner 單段 ≤ 5 分鐘）、`cohere-transcribe`（本機；無時間戳，僅作文字比對）。
   - 模型首次使用需下載，執行前確認磁碟與網路。
3. 差異句段標記：
   - 轉寫字與原文不同且音近 → 多為誤讀，進入替換。
   - 轉寫字與原文同字 → 通過。
   - 辨識本身的誤差（簡繁、同音字）需人工判斷，勿因 ASR 錯而亂加替換。
4. 人工試聽被標記之句段（每段 1 次，記錄於 `report` 或工作日誌）。

### 4.3 修正與重生

1. 更新 `project.json` 之 `pronunciations`。
2. 執行 `python <repo>\scripts\tts_batch.py <repo>\projects\<slug> --only <chNN>`。
   - 只有 `text_hash` 變動之句段重生，其他快取。
3. 重新抽查該章。
